# 后续缺口：文本筛选、UUID 与原始文件

用户已明确授权持续多代理补全。完整 420 行核对揭示本批三类工作流，各自复用独立纯内核，原生 15 语、MCP 和生产浏览器一并验收。最多主任务加三个子代理并行，继续同一任务。

- 文本筛选：字面包含/排除、含首尾的一基行号范围、Unicode 码点长度范围、字面分隔列提取。保留空白与空行，CRLF/CR 规范为 LF。空输入零行，结尾 LF 是额外空行。列缺失策略由用户选拒绝或空字段。拒绝非法/超限，不截断。不在本批实现正则筛选，目录对应行保持部分覆盖。
- UUID：解析规范字符串、32 位十六进制、128 位二进制、标准有填充 Base64，兼容单层花括号或 UUID URN 输入。输出规范大小写、裸 HEX、URN、花括号、二进制、Base64 与字节。严格检查格式和 Base64 填充，区分解析成功、版本/变体规则和 NIL/MAX 特例；不声称验证随机性或唯一性。以 RFC 9562 向量为锚。
- 文件：按精确字节数或指定份数切分本地 Blob，列出有序下载分片；按用户顺序合并本地文件，支持重排和移除。字节回读必须与输入一致。总计上限 50 MiB、100 个文件/分片。拆分计划纯模块返回有界偏移，MCP 只返回计划，不传文件内容。文本语义拆分另保留缺口。

每个界面清楚显示结果和上限、提供清空与确认反馈、数据区 LTR、移动无溢出。文件下载以实际 Blob 产物回读，不用文件名或按钮存在作为验证。生产构建/测试/SEO/协议通过后再更新完整目录的交付状态，历史证据保持原样。
